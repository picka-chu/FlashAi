# Flash AI

Telegram Mini App for AI-assisted football match analysis, live match insights, and
betting-prediction history.

## Stack

- React + Vite + Tailwind frontend
- Hono + Node backend (`backend/server.ts`)
- Supabase Postgres (service-role access from the backend only)
- Telegram bot (Telegraf), Gemini AI
- Football data: ESPN (free, no key) + BSD/Bzzoiro (primary) + optional SportsAPI Pro v2
- Home feed news: ESPN per-league news, cached and exposed at `GET /api/football/news`
- Payments: Telegram Stars, Whop (cards, primary), Lemon Squeezy (fallback), TON Connect
- Engagement: bot digests, football news, live goal alerts, weekly recap, win-back/upgrade campaigns

## Local development

**Prerequisites:** Node.js 20+ and a Supabase project.

1. Install dependencies: `npm install`
2. Copy `.env.example` to `.env` and fill in the required values.
3. Apply the database schema in the Supabase SQL editor:
   `CONSOLIDATED_PRODUCTION_SCHEMA.sql` (idempotent; safe to re-run).
4. Start the app: `npm run dev`

The Vite dev server proxies `/api` to the backend. In production the backend
serves the built frontend from `dist/`.

## Production deployment (Render / any Node host)

- **Build command:** `npm install && npm run build`
- **Start command:** `npm run start`
- **Health check:** `GET /api/health`
- **Database:** run `CONSOLIDATED_PRODUCTION_SCHEMA.sql` before the first deploy.
  It creates all tables, indexes, RPCs, and RLS policies.
- **Environment:** every server secret belongs in the host's environment, never
  in the repo. `SUPABASE_SERVICE_ROLE_KEY`, `TELEGRAM_BOT_TOKEN`,
  `LEMONSQUEEZY_WEBHOOK_SECRET`, and `TONCENTER_API_KEY` are required for the
  features that use them.
- **Reverse proxy:** set `TRUST_PROXY=true` only when the app is behind a trusted
  proxy, so rate limiting can use `X-Forwarded-For`.
- **Whop (recommended card provider):** set `WHOP_API_KEY`, `WHOP_ACCOUNT_ID`,
  `WHOP_PLAN_MONTHLY_BASIC`, `WHOP_PLAN_MONTHLY_PRO`, and
  `WHOP_WEBHOOK_SECRET`. Point the webhook to
  `POST /api/payments/whop-webhook` and subscribe to `payment.succeeded`.
  Card checkout uses Whop when configured and otherwise falls back to Lemon
  Squeezy. Both webhooks fail closed without their signing secret.
- **Lemon Squeezy (fallback):** point the webhook to
  `POST /api/payments/lemonsqueezy-webhook` and enable the
  `order_created`, `order_paid`, and `subscription_payment_success` events.
- **TON:** configure `TON_RECEIVER_ADDRESS` and `TONCENTER_API_KEY`. Every
  payment must include the intent comment generated by the app.
- **Engagement scheduler:** `NOTIFICATIONS_ENABLED=true` (default). Users manage
  preferences in the bot with `/settings`, `/timezone`, and `/stop`. The
  scheduler sends a daily fixture digest, one daily ESPN news digest, live
  goal/full-time alerts for followed matches, a Monday recap, and capped
  win-back/upgrade campaigns. Quiet hours default to 22:00–08:00 in the user's
  timezone. Delivery is deduplicated in `notification_deliveries`, so restarts
  and overlapping ticks cannot double-send.

## Security notes

- All backend secrets stay server-side. Only `VITE_*` values are shipped to the
  browser.
- Telegram `initData` is HMAC-verified with an age limit; client-supplied user
  IDs are never trusted.
- All credit/task/payment grants are idempotent or guarded by unique
  constraints. Run the schema migration before deploying payment changes.
- Rotate any secret that has ever been shared in chat, a commit, or a screenshot.
